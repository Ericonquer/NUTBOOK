# Markdown 演示 HTML：内容保全与明确对比分组

适用：Balanced / Report 演示 HTML。Master 继续使用原有提纲摘取策略，不属于全文保全模式。

## 混合主题

关系版式不能完整表达主题中的前提、公共说明、图片、表格或代码时，导出使用普通页或卡片保留内容。语义版式不优先于内容保全。未知关系保留源文顺序。

导出结果的 diagnostics 是结构化诊断，sourceId 标识本次生成中的章节与主题，content-preserving-fallback 表示使用普通排版保全内容。该信息展示在导出状态，不写入 HTML 正文。图片失败继续通过独立 warnings 返回。

## 明确对比

comparison 指令只指定版式意图，不能证明分组。当前首期仅支持下面的明确 A/B 根列表，两个根的子项维度名称与顺序必须一致、均有值，不能有更深层级或根级附加说明。不满足时保留普通排版，绝不按条目数中点切分。

```markdown
### 方案比较
<!-- nutbook:layout comparison -->
- **A**
  - **价格**：10元
  - **速度**：快
- **B**
  - **价格**：20元
  - **速度**：慢
```

每一栏使用作者给定的维度和值；不会猜测任意名称的比较对象或从交错列表推断配对。

## 来源覆盖检查

内部生成结果 coverage 记录章节、主题、块、列表项身份及匹配到的页码。非 Master 输出按渲染 DOM 的文本与图片 alt 检查来源文本是否依次出现；忽略脚本、样式、空白及可被卡片标题分隔替代的冒号。检测到遗漏时生成失败，不把不完整文件写盘。

该检查是文本保全防线，不能证明语义理解、图片实际加载成功、唯一归属或视觉布局正确。重复文字可能存在多个匹配位置，页码是本次匹配结果，不作为跨版本身份。图片加载与 A/B 数值对应另由资源、浏览器和真实产品验收检查。

## 真实验收入口

接入 docs/presentations/markdown-rule-acceptance/sample.md → 导出中心 → 演示 HTML → 导出 → 添加生成 HTML → 检查前提、失败处理、图片、歧义列表与明确对比 → 编辑正文 → 保存 → 关闭重开。

自动回归覆盖明暗、16:9/4:3、Balanced/Report、静态/动态。真实 WKWebView 编辑保存、取消和关闭重开由用户确认；自动浏览器结果不代表这部分验收通过。
