# Nutbook Markdown 导出中心设计

> 面向 Nutbook 下一阶段“产物交付”能力的第一份规格。目标是先把 Markdown 导出 HTML 做成稳定、可扩展的小闭环，再逐步接入 PDF、长图、水印和更强的演示能力。

## 1. 设计结论

第一阶段新增 `Markdown 导出中心`：

- 入口放在 Markdown 页面的更多菜单中，显示为 `导出...`
- 点击入口后先处理未保存修改，再打开紧凑导出弹窗
- 第一版只启用 `HTML` 导出
- `PDF`、`长图` 作为后续能力在设计中预留，不在第一版实现
- HTML 模板分为三类：
  - `阅读 HTML`
  - `展示 HTML - Light`
  - `展示 HTML - Dark`
- 有未保存修改时，进入导出中心前提供二选一：
  - `保存并继续导出`
  - `取消导出`

本设计只触及 Markdown 导出链路，不修改 HTML runtime、child webview、HTML controls overlay、演示模式和画笔工具。

## 2. 产品目标

Nutbook 当前已经能管理、阅读和轻编辑 Markdown。下一步需要增强“把产物带出去”的能力。

第一阶段目标不是一次性完成所有格式，而是建立一个可持续扩展的导出入口：

1. 用户能把当前 Markdown 导出为可独立打开的 HTML 文件。
2. 用户能选择偏阅读或偏演示的模板。
3. 用户有未保存修改时，不会误导出旧内容；必须保存并继续导出，或取消导出。
4. 后续 Markdown PDF、长图、水印和 AI 转演示 HTML 能接入同一个 Markdown 导出中心，而不是继续挤进更多菜单。

## 3. 范围边界

### 3.1 第一版包含

- Markdown 页更多菜单新增 `导出...`
- 紧凑导出弹窗
- HTML 格式选择
- 三个 HTML 模板选择
- 未保存修改处理
- 保存文件对话框
- 自包含 HTML 文件输出
- 基础导出状态提示和错误提示

### 3.2 第一版不包含

- PDF 生成
- Markdown 长图生成
- 水印参数配置
- HTML 文件提取文字并转换为 Markdown
- HTML 原生演示模式
- 演讲者视图、备注编辑、时钟
- 画笔工具
- 用户自定义模板编辑器
- AI 重排或 AI 生成演示 HTML

这些能力后续按独立小版本推进。

## 4. 导出中心交互

### 4.1 入口

Markdown 页面右上角更多菜单中新增或替换为：

```text
保存
导出...
```

`导出...` 仅在当前标签页是 Markdown 时可用。HTML runtime 页面不复用这个弹窗，避免跨越 HTML runtime 边界。

点击 `导出...` 后的顺序：

1. 先检查当前 Markdown 是否有未保存修改。
2. 如果有未保存修改，先显示保存确认。
3. 用户选择 `保存并继续导出` 且保存成功后，再打开导出弹窗。
4. 用户选择 `取消导出` 时，不打开导出弹窗。
5. 如果没有未保存修改，直接打开导出弹窗。

这样导出弹窗只负责“选择导出格式和模板”，不承担保存分支。

### 4.2 弹窗结构

弹窗采用紧凑 modal：

- 标题：`导出 Markdown`
- 格式区：
  - `HTML` 可选
  - `PDF` 禁用，显示后续能力提示
  - `长图` 禁用，显示后续能力提示
- 模板区：
  - `阅读 HTML`
  - `展示 HTML - Light`
  - `展示 HTML - Dark`
- 底部操作：
  - `取消`
  - `导出 HTML`

第一版不做右侧面板。等 PDF、长图、水印和模板预览都进入后，再评估是否升级成更完整的导出工作台。

### 4.3 未保存修改

进入导出中心前检查当前 Markdown tab 是否存在未保存修改。判断应沿用已有 Markdown 编辑模型：

- 当前内容来自 `markdownContentForTab(tab)`
- baseline 使用现有 `markdownBaseline`
- 不新增一套脱离编辑器的 dirty 判断

如果没有未保存修改，直接打开导出弹窗。

如果有未保存修改，先显示应用级确认弹窗：

```text
当前 Markdown 有未保存修改。导出前需要先保存。

保存并继续导出
取消导出
```

行为：

- `保存并继续导出`：先调用现有保存链路，保存成功后打开导出弹窗
- `取消导出`：关闭确认弹窗，不打开导出弹窗

不能静默导出磁盘旧内容，也不提供“只导出草稿但不保存源文件”的分叉路径。导出代表交付动作，应以已保存文件为准。

保存失败时，不打开导出弹窗，并显示保存失败状态。

### 4.4 与未来 HTML 导出能力的边界

当前导出中心第一版只服务 Markdown 文件。未来如果 HTML 文件需要导出 Markdown、PDF 或截图，不能直接复用这个主 DOM 弹窗。

原因：

- HTML 文件运行在 HTML runtime / child webview 边界内
- 主 DOM modal 不能保证稳定浮在 HTML runtime 内容之上
- 项目已经明确：叠在 HTML runtime 上的菜单、tooltip、控制层优先走宿主 overlay

因此，未来 HTML 导出需要单独设计 runtime 兼容入口：

- 入口可以出现在 HTML controls overlay 的更多菜单中
- 弹窗或面板应走宿主 overlay / 独立 webview overlay，而不是主页面 DOM modal
- 转换能力本身可以复用后端导出服务，但交互承载层必须与 Markdown 区分

也就是说，`导出中心` 是产品概念可以统一，技术承载层不能强行统一。

## 5. HTML 模板

### 5.1 模板目录

第一版建议建立模板目录：

```text
dist/export-templates/
  markdown-reading.html
  markdown-showcase-light.html
  markdown-showcase-dark.html
```

模板目录的意义：

- 避免把大段 HTML/CSS 作为 Rust 字符串长期维护
- 让视觉模板与应用静态资源保持同一层级
- 为后续新增模板、AI 模板和模板预览留出清晰边界

Rust 侧负责读取模板、注入渲染后的内容和元数据，再写出用户选择的目标文件。

### 5.2 阅读 HTML

`阅读 HTML` 是完整长文模板，不拆页。

视觉原则：

- 贴近 Nutbook Markdown 阅读页
- 保持 `DESIGN.md` 的 Ink & Paper 风格
- 使用黑白灰、纸张层次、8px 圆角、低调阴影
- 适合归档、分享、打印前预览

内容规则：

- 保留完整 Markdown 渲染结构
- 标题、段落、引用、列表、代码块、表格应可读
- 底部可显示轻量 `by NUTBOOK`

### 5.3 展示 HTML - Light

`展示 HTML - Light` 是类 PPT 的静态翻页 HTML。

视觉原则：

- 基于 `DESIGN.md` 的浅色 Ink on Paper
- 白纸黑字，克制留白
- 不引入额外品牌色
- 适合技术文档、规格、复盘和方案展示

交互规则：

- 使用 `Showcase Summary` 拆页策略，把长 Markdown 转为适合演示的提要 slides
- 支持左右键翻页
- 支持空格下一页
- 显示页码
- 底部显示小水印：`by NUTBOOK`
- 长文字可在当前 slide 内点击展开原文
- 代码块和表格在放不下时用压缩窗口展示，并可点击打开大弹层查看完整内容

### 5.4 展示 HTML - Dark

`展示 HTML - Dark` 是 `展示 HTML - Light` 的深色投屏版本。

视觉原则：

- 基于 `DESIGN.md` 的 inverse surface
- 深灰背景、白色主文字、灰色辅助文字
- 保持黑白灰，不做彩色舞台风
- 适合投屏和现场讲解

交互和拆页规则与 Light 模板一致。

### 5.5 Showcase Summary 拆页规则

展示 HTML 第一版不做全文铺排，也不做 AI 改写摘要。它采用 `Showcase Summary` 规则：

- 主 slide 展示结构化提要，适合讲解
- 长文字、代码块、表格保留完整内容，但默认收纳
- 用户可以在需要时展开详情

这个策略的目标是：演示时不拥挤，信息不丢失，且所有取舍规则可解释。

#### 5.5.1 结构骨架

1. 如果文档存在第一个 `H1`，它作为封面标题。
2. `H2` 默认生成章节 slide 或内容 slide。
3. `H3/H4` 优先作为内容 slide 的标题，而不是全部塞进上一级 slide。
4. 如果开头没有 `H1/H2`，则生成一个默认封面页，并把开头内容放入第一组内容 slide。
5. 第一版不做 AI 重排、不做自动改写、不做自动图文配比。

#### 5.5.2 内容预算

每个 slide 设定一个内容预算。预算不是精确排版引擎，而是避免明显拥挤的规则。

建议第一版用块权重估算：

```text
标题 = 2
短段落 = 2
长段落 = 4
列表项 = 1
引用块 = 3
短代码块 = 5
长代码块 = 8
小表格 = 5
大表格 = 8
每页预算 = 10-14
```

超过预算时，不继续压缩字号，也不把所有内容硬塞进一页，而是拆为下一张 slide 或收纳为详情。

#### 5.5.3 文字提要与展开

文字内容按小节生成提要：

- 优先显示小节标题
- 保留第一段
- 保留前 3 到 5 个列表项
- 保留显式重点内容，例如加粗文本、引用块、`结论`、`建议`、`风险`、`步骤`、`注意`
- 超过预算的长文字不默认铺开

被收纳的长文字在当前 slide 内提供按钮：

```text
展开原文 / 收起原文
```

点击后在当前 slide 内展开完整原文。文字详情采用页内展开，不另开弹层，避免打断阅读上下文。

#### 5.5.4 代码块

代码块不做摘要改写，不丢行。

- 如果代码块能在当前 slide 舒适显示，则完整展示。
- 如果代码块太长，则显示固定高度代码窗口，窗口内部可滚动。
- 提供 `展开代码` 按钮，用居中大弹层展示完整代码。

大弹层应支持关闭，并尽量保持等宽字体、语法高亮和复制能力。

#### 5.5.5 表格

表格不做摘要改写，不丢列。

- 小表格完整展示。
- 大表格显示在固定尺寸表格窗口中，允许横向和纵向滚动。
- 提供 `展开表格` 按钮，用居中大弹层展示完整表格。
- 大弹层中表头尽量 sticky，便于查看。

#### 5.5.6 非目标

第一版不做以下能力：

- 自动判断“哪句话最重要”
- 自动改写为更短句子
- 自动删除内容
- 自动生成图表
- 自动把长表格改成结论图

这些属于 AI 演示 HTML 或更高级模板能力，后续作为单独模式设计。

## 6. 技术设计

### 6.1 前端状态

在主界面状态中新增导出弹窗状态：

```text
exportDialogOpen
exportFormat
exportTemplate
exportInProgress
```

第一版 `exportFormat` 只有 `html` 真正可用。`pdf` 和 `image` 可以在 UI 中显示为禁用项。

### 6.2 前端流程

导出 HTML 的流程：

```text
点击更多菜单“导出...”
  -> 检查当前 Markdown tab
  -> 检查未保存修改
  -> 必要时弹出二选一
  -> 保存成功或无未保存修改
  -> 打开导出弹窗
  -> 用户选择模板
  -> 点击“导出 HTML”
  -> 读取已保存 Markdown 内容
  -> 调用 Tauri command
  -> 后端打开保存文件对话框并写出 HTML
  -> 前端展示成功或失败状态
```

### 6.3 后端命令

新增 Tauri command：

```text
export_markdown_html(item_id, content, template)
```

参数：

- `item_id`：用于读取文件名、标题、路径等元数据
- `content`：前端确认后的已保存 Markdown 内容
- `template`：`reading`、`showcase-light`、`showcase-dark`

行为：

1. 校验 item 是 Markdown。
2. 用系统保存对话框选择目标路径。
3. 默认文件名从源文件名派生，扩展名改为 `.html`。
4. 使用现有 Markdown 渲染函数生成 HTML 内容。
5. 按模板类型生成最终 HTML。
6. 写入目标文件。

后端不自行判断当前编辑器是否 dirty。前端必须在未保存修改处理完成后，只把已保存内容交给后端。

### 6.4 模板渲染边界

建议新增独立模块承载导出渲染：

```text
src-tauri/src/core/markdown_export.rs
```

职责：

- 渲染阅读 HTML
- 渲染展示 HTML
- 按 `Showcase Summary` 规则拆分 Markdown slides
- 为长文字、长代码块和大表格生成详情数据
- 注入模板变量
- 保证导出 HTML 自包含

不放入数据库层，不绑定缩略图层，不复用 HTML runtime host。

## 7. 错误处理

需要覆盖的错误场景：

- 当前 tab 不是 Markdown
- 用户取消保存文件对话框
- 模板文件缺失
- 目标路径写入失败
- 保存并继续导出时 Markdown 保存失败
- Markdown 渲染后为空内容

用户取消保存文件对话框应作为中性取消，不显示红色错误。

模板文件缺失和写入失败应显示明确错误，方便定位打包资源问题。

## 8. 后续小版本顺序

### 8.1 PDF 导出

PDF 导出应优先复用 `阅读 HTML` 模板，再解决分页、字体、页边距和打印样式。

第一轮不要把 PDF 与展示 HTML 绑定。PDF 的核心是稳定交付，不是演示。

### 8.2 长图导出

长图导出应复用 Markdown 阅读渲染，并加底部小水印：

```text
by NUTBOOK
```

截图引擎需要结合已有 thumbnail / Chromium 结论，不能静默后台调 Chrome。

### 8.3 HTML 提取 Markdown

HTML 转 Markdown 是转换能力，不属于导出中心第一版。

应单独设计：

- 读取 HTML
- 提取正文结构
- 转成 Markdown
- 保留标题层级、列表、链接、代码块

### 8.4 HTML 原生演示模式

HTML 原生演示模式属于 runtime 能力，不属于导出中心。

必须遵守项目已有边界：

- 不回退 iframe 主路线
- 不把演示控制 DOM 浮层放回 HTML 内容层
- 备注、时钟、演讲者窗口和全屏控制需要走 runtime / overlay 专项设计

### 8.5 画笔工具

画笔工具依赖演示 overlay 边界。

建议放在 HTML 原生演示模式之后，作为 Markdown 和 HTML 共用的演示控制能力设计。

### 8.6 第三种文件视图

第三视图是管理效率专项：

- 左侧纯文件名列表
- 右侧缩略图预览栏
- 复用已有缩略图缓存

它可以独立排期，不依赖导出中心。

## 9. 验证计划

第一版实现后至少验证：

```bash
npm run build:frontend
npm run check:frontend
cargo check --manifest-path src-tauri/Cargo.toml
```

建议补充 Rust 单测：

- 阅读 HTML 包含 Markdown 标题和正文
- 展示 HTML 能按标题结构拆 slide
- 长文字会生成页内展开详情
- 长代码块会生成压缩代码窗口和完整代码弹层数据
- 大表格会生成压缩表格窗口和完整表格弹层数据
- Light / Dark 模板输出不同主题 class
- Markdown 中的 HTML 被安全转义
- 默认导出文件名使用 `.html`

建议前端手测：

- 更多菜单能打开导出弹窗
- 非 Markdown 页面不显示或禁用导出入口
- 无未保存修改时可直接打开导出弹窗
- 未保存修改时二选一行为正确，取消时不打开导出弹窗
- 保存失败时不打开导出弹窗
- 取消保存文件对话框不会显示红色错误
- 导出的 HTML 可在浏览器独立打开

## 10. 开发切分

每次开发一个小功能，建议按以下顺序：

1. 建立后端 `markdown_export` 模块和 `阅读 HTML` 渲染单测。
2. 加 Tauri command 和保存文件对话框，只支持 `阅读 HTML`。
3. 加前端导出弹窗壳子，只启用 `HTML`。
4. 接入未保存修改二选一。
5. 增加 `展示 HTML - Light` 拆页模板。
6. 增加 `展示 HTML - Dark` 拆页模板。
7. 做完整验证和打包资源检查。

这样每一步都有可验收产物，且不会提前进入 PDF、截图、HTML runtime 或画笔的复杂边界。
